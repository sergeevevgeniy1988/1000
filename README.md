# «Тысяча» (1000)

Браузерная карточная игра «Тысяча» на троих. Игра работает офлайн в одиночном режиме и по сети через интернет: статический фронтенд размещён на GitHub Pages, а небольшой Node-relay — на Render. Без фреймворков, сборщиков, CDN и внешних изображений.

## Статус

Версия 1.3.0: закрыты четыре замечания тестировщика. После прикупа заказ можно один раз повысить до 120 плюс бонусы марьяжей на руке (не выше 400), повышение вынесено в инлайн-панель с видимой рукой и вводом суммы, карта отдара видна только отдающему и получателю, а в панелях игроков показывается набранный счёт текущей раздачи. Торговля по-прежнему идёт 80–120. Сетевой режим через интернет (Render relay, прототип), локальная одиночная партия, `?seed=` и `?target=` сохранены.

## Что нового в v1.3.0

- Заказ после прикупа: максимум — 120 плюс бонусы всех марьяжей на руке играющего, до 400. Аукцион остаётся 80–120, ставка 120 немедленно завершает торги.
- Обязательная модалка повышения заказа заменена инлайн-панелью основного стола: видна своя рука, текущий заказ и максимум, сумма вводится вручную с шагом 5.
- Приватность отдара: карту видят только отдающий и получатель. Третий игрок и компьютер получают снимок без достоинства и масти, а в общем журнале остаётся только факт передачи.
- В панели каждого игрока во время розыгрыша и подсчёта появилась строка «В партии: N» — набранный счёт текущей раздачи.

## Что нового в v1.2.0

- Отдельный лаунчер `start-lan.cmd`: сервер слушает только частный IPv4-адрес и печатает LAN-адрес. Обычный `start.cmd` остаётся одиночным режимом только на `127.0.0.1`.
- Комнаты с кодом из 6 символов, ссылка-приглашение вида `http://<адрес>:<порт>/?room=ABC234`, имена 1–24 символа, места `human`/`alice`/`boris`.
- За столом 1–3 живых человека; свободные места автоматически занимает компьютер. AI никогда не управляет живым местом.
- Авторитетный хост: действия гостей уходят на сервер, хост проверяет их игровым ядром и публикует каждому игроку только его снимок стола.
- Переподключение гостя после reload или потери Wi-Fi: токен хранится в `localStorage`, место и карты восстанавливаются; при обрыве показывается «нет связи», хост ждёт возвращения игрока.
- Автоматические проверки безопасности, приватности, документации и сценариев сети: `tests/net-*.test.js`.

## Изменения v1.1.0

- Открытие торгов — 80; диапазон 80–120 с шагом 5; игрок с отрицательным счётом не торгуется: он обязан открыть 80, авто-пас происходит, только если он не выиграл торги.
- После торгов прикуп раскрывается всем; играющий забирает его отдельным действием.
- После взятия прикупа играющий один раз повышает заказ до первой карты отдара, не выше 120; подсчёт использует финальный заказ.
- Марьяж объявляется как pending-состояние; бонус и козырь появляются только после выхода королём или дамой объявленной масти. До хода объявление можно отменить.
- Обновлены правила, онбординг, AI и тесты.

## Запуск: локальная игра

1. Установите Node.js 18+ — он нужен и для локального сервера, и для relay.
2. В корне проекта выполните `npm start`.
3. Откройте в браузере `http://127.0.0.1:8787/` — сервер отдаст статику игры и API relay.
4. После игры остановите сервер сочетанием `Ctrl+C`.

Порт можно изменить переменной окружения `PORT`, адрес прослушивания — `HOST`. По умолчанию сервер слушает только `127.0.0.1`.

Для воспроизводимой партии добавьте к адресу `?seed=12345`. Для быстрой проверки финального экрана можно временно понизить цель: `?target=150` (по умолчанию цель — 1000).

> Не открывайте `index.html` напрямую через `file://` — ES-модули в этом режиме не загрузятся.

## Сетевая игра через интернет (Render)

Фронтенд игры и приглашения остаются на GitHub Pages, а relay — отдельный Node-сервис на Render. Гостям не нужно ничего устанавливать: достаточно браузера и ссылки.

1. Разверните relay по инструкции `docs/RENDER.md` (Blueprint из `render.yaml` или Web Service вручную). Сервис должен слушать `HOST=0.0.0.0`, а `FRONTEND_ORIGINS` — содержать `https://sergeevevgeniy1988.github.io`.
2. Проверьте `https://<service>.onrender.com/api/health`: в ответе должно быть `"ok": true` и `"network": true`.
3. Впишите адрес сервиса без завершающего слэша в meta `relay-base-url` в `index.html` и перепубликуйте Pages.
4. Откройте Pages, нажмите «Сетевая игра» и создайте комнату. Скопируйте ссылку-приглашение с `?room=CODE`: она ведёт на `github.io`, а не на адрес Render.
5. Гости открывают ссылку в своих браузерах. Используйте отдельные профили браузера, а не две вкладки одного профиля: один игрок — одна вкладка.
6. Всего за столом 1–3 живых человека. Свободные места занимает компьютер; хост всегда играет.
7. Хост нажимает «Начать игру». Вкладка хоста должна оставаться открытой и, желательно, видимой до конца партии.
8. При reload или потере связи гость возвращается на своё место по сохранённому токену. Пока гость не отвечает, интерфейс показывает «нет связи», и партия ждёт его хода.
9. «Выйти» освобождает место гостя. «Закрыть комнату» завершает сетевую игру для всех.

Без заполненного `relay-base-url` на Pages сетевой режим покажет, что сервер недоступен, а локальная одиночная игра продолжит работать. Пустое значение meta означает same-origin — так сетевой режим работает при локальном запуске.

Для локальной сетевой проверки запустите `npm start` и откройте игру на `http://127.0.0.1:8787/`; второй игрок в той же сети может подключиться по адресу `http://<IP-хоста>:8787/`, если сервер запущен с `HOST=0.0.0.0` и порт разрешён firewall. Это лишь удобство локальной отладки: основной сценарий прототипа — интернет через Render.

Код комнаты и ссылка-приглашение не содержат токенов. Токен передаётся только в заголовке `X-Room-Token` и хранится в браузере: гостевой — в `localStorage`, хостовый — в `sessionStorage`.

## Ограничения сетевого режима

- Вкладка хоста должна быть открыта. Закрытие или перезагрузка вкладки хоста завершает партию; восстановление состояния после reload хоста и host migration не поддерживаются.
- Render Free засыпает примерно через 15 минут без запросов и просыпается около минуты. Первый запрос после сна может показать недоступность — нажмите «Проверить снова».
- Relay хранит комнаты только в памяти, без базы данных и диска. После перезапуска или сна Render комнаты исчезают, а гости получают `410`; партию нужно начать новой комнатой.
- В интернете соединение идёт по HTTPS (его даёт Render), локальный relay работает по HTTP на loopback или в доверенной локальной сети.
- Нет аккаунтов, рейтингов, матчмейкинга, чата, зрителей и нескольких партий в одной комнате.
- Один игрок — одна вкладка/профиль. Повторный вход с другим токеном не подменяет живое место.
- Защита от злоупотреблений базовая: число комнат (`MAX_ROOMS`), размеры тела запроса, очереди действий и снимков. Отдельного rate limit по IP нет.

## Безопасность

- CORS: точный allowlist `FRONTEND_ORIGINS` без wildcard; для Pages разрешён только `https://sergeevevgeniy1988.github.io`, для локальной проверки — `http://localhost:8787` и `http://127.0.0.1:8787`. Сервер отвечает `Vary: Origin`, не включает `Allow-Credentials`, а чужой `Origin` получает `403 bad_origin`.
- Токены комнаты передаются только в заголовке `X-Room-Token`, сравниваются timing-safe способом и не попадают в URL, `location`, журнал и логи сервера.
- В интернете используется HTTPS Render; запросы с Pages идут на HTTPS-адрес сервиса. Локальный relay слушает loopback и не предназначен для публичного доступа.
- Проект не устанавливает службы, драйверы и расширения, не создаёт автозапуск, записи реестра, firewall-правила и не скачивает файлы. В репозитории нет exe/dll/msi.
- Сервер ограничивает размер заголовков и тела, число комнат, очередь действий и сообщений, проверяет коды комнат и защищён от path traversal. Статика раздаётся только по allowlist (`/`, `/index.html`, `/css/*`, `/js/*`, `/favicon.svg`), хотя на Render она не нужна: фронтенд отдаёт Pages. Раздачу можно отключить переменной `SERVE_STATIC=0`.
- Relay не хранит данные: имена, токены и снимки стола живут только в памяти процесса и исчезают при перезапуске. Секретов в репозитории и в ответах API нет.

## Требования

- Современный браузер: Chrome, Edge или Firefox.
- Node.js 18+ — для локального запуска и relay. Для самой игры в браузере Node.js не требуется.
- Для интернет-режима — аккаунт Render (Free) и доступ к GitHub Pages. Локальная сеть, общий ПК и входящие порты не нужны.

## Архитектура

- Игровое ядро отделено от DOM и браузера. UI не изменяет состояние напрямую, а вызывает методы сессии и перерисовывается по событиям.
- `LocalSession` владеет `Game` в одиночной партии. `HostSession` оборачивает `LocalSession`, применяет проверенные действия гостей и публикует снимки. `GuestSession` опрашивает сервер и отправляет действия.
- Авторитетное состояние остаётся в браузере хоста. Сервер в `server/` только пересылает непрозрачный JSON и хранит комнаты в памяти.
- Обмен идёт коротким polling (350–500 мс). При отсутствии изменений сервер не повторяет снимок стола.
- Каждый игрок получает только свой `player view`: чужие руки пусты, скрытый прикуп пуст до публичного раскрытия, полный `log` в снимок не входит.
- AI получает только `getPlayerView` своего места и действует только на свободных местах.
- Все случайные решения идут через внедряемый RNG, поэтому тесты и партии с `?seed=` детерминированы.

## Правила, обучение и настройки

- Кнопка «Правила» в шапке открывает полный текст правил с таблицами стоимости карт и марьяжей, примерами подсчёта и разделом «Что не реализовано в версии 1.3.0». Текст хранится в `js/content/rules.js`, числа берутся из игровых констант. Правила описывают торговлю 80–120, повышение заказа после прикупа до 120 плюс бонусы марьяжей на руке, приватность карт отдара и заметку о сетевом режиме и компьютере на свободных местах.
- При первом запуске показывается обучение из трёх шагов. Факт прохождения записывается в `localStorage` под ключом `1000.onboarding.v1`.
- Настройки звука и анимаций применяются сразу и сохраняются под ключом `1000.settings.v1`. При выключенных анимациях также отключаются CSS-переходы.
- Звук синтезируется через WebAudio без аудиофайлов. Аудиоконтекст создаётся только после первого жеста пользователя, поэтому автозапуска нет.
- Системная настройка `prefers-reduced-motion` имеет приоритет: анимации не запускаются, даже если в настройках игры они включены.

## Доступность и адаптивность

- Все игровые действия доступны с клавиатуры: `Tab`, `Enter`, `Space`, `Escape`. После перерисовки стола фокус сохраняется на той же кнопке или переходит на первую легальную карту либо на панель действий.
- У карт-кнопок есть `aria-label` с достоинством, мастью, стоимостью и подсказкой о легальности; нелегальные карты исключены из порядка обхода.
- Обычные модальные окна удерживают фокус и закрываются по `Escape`; обязательные окна — раскрытие и взятие прикупа, отдар, итоги раздачи и финал — закрываются только явным действием. Повышение заказа идёт не в модалке, а в инлайн-панели панели действий, поэтому стол и рука остаются видимыми. Фон получает `inert`. Для журнала и смены фаз используется `aria-live="polite"`.
- На экранах до 900 px журнал превращается в выдвижную панель с фокус-трапом; страница не прокручивается горизонтально, а рука при нехватке места прокручивается внутри своей области.
- Проверены размеры 1280×800, 1024×768, 800×600, 740×360 и 390×844. Визуальная проверка выполнена в Chrome и Edge; Firefox использует поддерживаемые стандартные API (`inert`, `matchMedia`, `safe center`).

## Тесты и проверка

Набор тестов 1.3.0 в репозитории не восстановлен: каталога `tests/` нет, поэтому `npm test` сейчас не запускается (скрипт оставлен как заготовка). Прототип интернет-режима проверяется смоук-командами:

- `node --check` для `server/*.js` и изменённых модулей `js/` — синтаксис;
- запуск `npm start` и `GET /api/health` — сервер отвечает `{ "ok": true, "network": true }`;
- создание комнаты, join, publish, host/player polling, действие гостя, kick и close — по контракту API из `server/http.js`;
- CORS-preflight с `Origin: https://sergeevevgeniy1988.github.io` — `204` и точный `Access-Control-Allow-Origin`, чужой origin — `403`;
- статика `/`, `/js/config.js` и path traversal (`/../server/index.js` — `404`).

Полный сценарий и ожидаемые ответы описаны в плане разработки; после деплоя добавьте проверку из `docs/RENDER.md`. Реальный e2e из двух разных сетей, холодный старт Render и браузерный CORS автоматическими тестами не покрываются.

## Решение проблем

- **Порт занят.** Задайте другой порт: `$env:PORT='8788'; npm start` (PowerShell) или `PORT=8788 npm start` (POSIX). По умолчанию используется 8787.
- **`npm start` не запускается.** Нужен Node.js 18+ в `PATH`; проверьте `node --version`.
- **Сервер сетевой игры не отвечает.** Render Free может спать: подождите до минуты и нажмите «Проверить снова». Проверьте `https://<service>.onrender.com/api/health`.
- **403 `bad_origin`.** `FRONTEND_ORIGINS` должен содержать ровно `https://sergeevevgeniy1988.github.io` — без `/1000` и без слэша на конце.
- **404 `room_not_found`.** Проверьте код комнаты; она могла истечь по TTL (120 секунд без активности хоста) или исчезнуть после сна Render.
- **410 `room_closed`.** Комната закрыта хостом, истекла по TTL или пропала после перезапуска relay. Создайте новую.
- **Гость потерял связь или перезагрузил страницу.** Откройте ту же ссылку: место восстановится по сохранённому токену. Если хост закрыл комнату, появится сообщение об этом.
- **Хост закрыл или перезагрузил вкладку.** Партия завершается; восстановление состояния хоста не поддерживается. Начните новую комнату.
- **Браузер не открылся.** Откройте вручную `http://127.0.0.1:8787/` (или адрес Render для same-origin запуска).
- **Пустая страница или ошибки модулей.** Откройте игру через `npm start` или Pages, а не через `file://`.
- **Кириллица или пробелы в пути.** Поддерживаются: сервер определяет корень проекта от `server/index.js`, а не от текущего каталога.

## Известные ограничения

- За столом не более трёх игроков; в сетевом режиме живых людей 1–3, остальные места играет компьютер.
- Нет «бочки», «самосвала», «золотого кона», игры «втёмную» и тузового марьяжа.
- Нет пересдачи, росписи и торговли выше 120. Выше 120 может быть только заказ после прикупа за счёт марьяжей на руке играющего.
- Интернет-режим — прототип через Render relay: без аккаунтов, рейтингов, чата, зрителей, матчмейкинга и host migration.
- Нет восстановления партии после перезагрузки вкладки хоста.
- Обучение показывается только при первом запуске; повторно открыть его из интерфейса нельзя.
- `PROMPT.md` в корне проекта — исходное ТЗ версии 1.1.0. Расхождения с ним ограничены добавлением интернет-relay в прототипе и исправлениями 1.3.0; они описаны здесь, в правилах и в `ACCEPTANCE.md`.
