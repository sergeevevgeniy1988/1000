# Деплой relay «Тысячи» на Render

Интернет-режим устроен так: статический фронтенд игры лежит на GitHub Pages
(`https://sergeevevgeniy1988.github.io/1000/`), а небольшой Node-relay — на
Render. Relay не считает игру и не хранит партии: он только передаёт действия
гостей хосту и персональные снимки стола гостям. Комнаты живут в памяти
процесса и исчезают при перезапуске или сне сервиса.

Деплой выполняется один раз. После него достаточно вписать адрес сервиса в
`index.html` и перепубликовать Pages.

## 1. Аккаунт и репозиторий

1. Создайте аккаунт на <https://render.com> (можно войти через GitHub).
2. Убедитесь, что репозиторий игры доступен Render: при входе через GitHub
   выдайте доступ к нужному репозиторию (Render попросит выбрать репозитории).
3. В репозитории уже есть `render.yaml`, `server/` и скрипт `npm start` —
   отдельная сборка не нужна, внешних npm-зависимостей нет.

## 2. Вариант А: Blueprint из `render.yaml`

1. В Render нажмите **New → Blueprint**.
2. Выберите репозиторий и ветку `main`.
3. Render прочитает `render.yaml` и создаст web-сервис `thousand-relay` с
   планом Free, командой сборки `npm install`, командой запуска `npm start`,
   health check `/api/health` и переменными окружения из файла.
4. Подтвердите создание и дождитесь окончания первого деплоя.

## 3. Вариант Б: Web Service вручную

1. В Render нажмите **New → Web Service**.
2. Подключите GitHub-репозиторий игры.
3. Заполните поля:
   - **Name:** `thousand-relay` (имя влияет на адрес `*.onrender.com`);
   - **Branch:** `main`;
   - **Runtime:** `Node`;
   - **Build Command:** `npm install`;
   - **Start Command:** `npm start`;
   - **Plan:** `Free`;
   - **Health Check Path:** `/api/health`.
4. В разделе **Environment** добавьте переменные:
   - `HOST` = `0.0.0.0` (обязательно: по умолчанию сервер слушает только
     `127.0.0.1` и Render не сможет до него достучаться);
   - `FRONTEND_ORIGINS` = `https://sergeevevgeniy1988.github.io` (точный
     origin Pages, без завершающего слэша; можно перечислить несколько через
     запятую);
   - `ROOM_TTL_SECONDS` = `120`;
   - `NODE_VERSION` = `22`.
5. Нажмите **Create Web Service** и дождитесь статуса **Live**.

Render выдаёт HTTPS-адрес вида
`https://thousand-relay.onrender.com`. Собственный домен и TLS настраивать не
нужно: HTTPS и сертификат предоставляет Render.

## 4. Проверка сервиса

1. Откройте в браузере `https://<service>.onrender.com/api/health`.
2. Ожидаемый ответ: JSON с `"ok": true`, `"network": true`,
   `"version": "1.3.0"` и `roomTtlSeconds`.
3. Если ответа нет, посмотрите **Logs** в Render: сервис пишет только метод,
   путь и статус запросов, без заголовков и тел.

## 5. Подключение Pages к relay

1. Откройте `index.html` и найдите в `<head>` строку:
   `<meta name="relay-base-url" content="">`.
2. Впишите в `content` адрес сервиса без завершающего слэша, например
   `https://thousand-relay.onrender.com`.
3. Закоммитьте изменение и отправьте его в GitHub — Pages перепубликует
   страницу автоматически.
4. Откройте `https://sergeevevgeniy1988.github.io/1000/`, нажмите «Сетевая
   игра»: лобби должно показать доступный сервер.

Пустое значение `relay-base-url` означает same-origin: так игра работает при
локальном запуске через relay, но на Pages сетевой режим сообщит, что сервер
недоступен. Локальная одиночная игра при этом продолжает работать.

## 6. Проверка после деплоя

1. Откройте `https://<service>.onrender.com/api/health` и убедитесь в
   `"ok": true`.
2. Откройте Pages, создайте комнату и скопируйте ссылку-приглашение.
3. Проверьте, что ссылка ведёт на `https://sergeevevgeniy1988.github.io/1000/`
   с параметром `?room=CODE`, а не на адрес Render: фронтенд и приглашения
   остаются на Pages.
4. Пригласите второго игрока в отдельный профиль браузера (не в соседнюю
   вкладку того же профиля), присоединитесь по коду, начните партию и
   убедитесь, что ходы гостя доходят до хоста, а снимок стола обновляется.
5. Закройте комнату кнопкой «Закрыть комнату»: гости должны получить
   сообщение о завершении.

## 7. Холодный старт и сон Render

- Render Free засыпает примерно через 15 минут без запросов.
- Первый запрос после сна может занять до минуты: лобби показывает
  «Проверяем сервер…», health-проверка делает две попытки по 30 секунд.
- Если сервер всё же не ответил, нажмите «Проверить снова» — второй запрос
  обычно успевает разбудить сервис.
- После сна или перезапуска все комнаты исчезают (они хранятся только в
  памяти). Гости получат `410`, текущую партию нужно начать заново новой
  комнатой.

## 8. Частые ошибки

- **403 `bad_origin`.** `Origin` страницы не совпадает с `FRONTEND_ORIGINS`.
  Сверьте схему, домен и порт: для Pages нужен ровно
  `https://sergeevevgeniy1988.github.io` (без `/1000` и без слэша на конце).
  После изменения переменной Render перезапустит сервис.
- **404 `room_not_found`.** Проверьте код комнаты: он состоит из 6 символов
  без похожих `0/O`, `1/I`. Комната могла истечь по TTL (120 секунд без
  активности хоста) или исчезнуть после сна Render.
- **410 `room_closed`.** Комната закрыта хостом, истекла по TTL или пропала
  после перезапуска сервиса. Создайте новую комнату и пригласите гостей
  заново.
- **Нет ответа на `/api/health`.** Проверьте, что `HOST=0.0.0.0`, команда
  запуска `npm start`, а деплой завершился статусом Live.
- **Сетевой режим недоступен на Pages.** Убедитесь, что `relay-base-url`
  заполнен HTTPS-адресом Render и Pages перепубликован после коммита.
- **CORS-ошибка в консоли браузера.** Проверьте точный `Origin` и что в нём
  нет завершающего слэша; при необходимости добавьте дополнительный origin в
  `FRONTEND_ORIGINS` через запятую.

## 9. Откат

- Быстрый откат интернет-режима: очистите `relay-base-url` в `index.html` и
  перепубликуйте Pages. Локальная игра продолжит работать, сетевой режим
  покажет недоступность сервера.
- Откат кода: в Render откройте **Deploys**, выберите предыдущий успешный
  деплой и нажмите **Redeploy**.
- Полная остановка: **Suspend** сервиса в Render. Pages останется статическим
  сайтом и продолжит работать без сети.

## 10. Ограничения прототипа

- Аккаунтов, рейтингов, чата, зрителей, матчмейкинга и host migration нет.
- Вкладка хоста должна оставаться открытой: состояние партии считается в
  браузере хоста.
- Relay ничего не пишет на диск и не использует базу данных; после
  перезапуска или сна Render комнаты исчезают.
- Защита от злоупотреблений базовая: лимит числа комнат (`MAX_ROOMS`,
  по умолчанию 200), лимиты тела запроса, очереди действий и размеров
  снимков. Отдельного rate limit по IP нет.
